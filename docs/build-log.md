# Build Log

What broke or surprised us while building, why, and what we did about it. This feeds the "what broke and how I fixed it" part of the video.

| Date | Finding | Why it matters | Decision / fix |
|---|---|---|---|
| 17 Nov | Company career boards (Greenhouse/Lever) had **0 real fresher roles** in ~175 live posts from Groww, InMobi, Druva, CRED and Meesho | They can't be the main source | Aggregator APIs supply the volume; career boards are a bonus source only |
| 17 Nov | Adzuna India works. Matches over the last 30 days: `fresher` 1,421, `intern` 2,128, `entry level` 652, `graduate trainee` 52. **197 unique posts from just page 1 of 5 queries** | 200+ posts is easily reachable from one source | Adzuna is the primary source; fetch 2–5 pages per query |
| 17 Nov | `intern` and `internship` return the **same** 2,128 results | Wasted API calls | Keep only one of the two queries |
| 17 Nov | Adzuna descriptions are **cut at 500 characters** | Less text for the LLM to tag fresher-fit, stipend and skills | Tag from title + 500-char snippet; measure the effect on accuracy in the 50-post check |
| 17 Nov | **65 of 197** posts have the location only as `"India"` | City tagging can't come from the location field alone | The LLM reads the description for a city; otherwise tag as `India (unspecified)`. Count these separately in the eval |
| 17 Nov | The same post appears twice with different dates (e.g. "Entry Level Associate", Ascendion, Vadodara, 15 Nov and 7 Nov) | Duplicates exist even within one source | The fuzzy dedup key ignores date; keep the earliest date |
| 17 Nov | Locations come as `"Bangalore, Karnataka"`, `"Gurgaon, Haryana"` | Old city names need mapping | City alias map: Bangalore→Bengaluru, Gurgaon→Gurugram |
| 17 Nov | User asked to switch the build from Maven to Gradle; Spring Initializr returned HTTP 500 and no longer offers Boot 3.5 | Couldn't download a starter with the Gradle wrapper | Generated the wrapper with a locally cached Gradle 9.8.2, pinned to Gradle 8.14.7 (supports Spring Boot 3.5) |
| 17 Nov | First full run: **653 raw → 596 after exact-URL dedup → 530 after fuzzy dedup** in 25 s | Dedup removed 19%; 66 removed only by fuzzy matching | Both passes are needed |
| 17 Nov | Company career boards again gave **1** entry-level India post (Groww) out of 174 | Confirms the research | Kept as a bonus source |
| 17 Nov | Many "fresher" search results are senior roles ("Senior Trading Specialist", "Collections Manager") | A keyword search alone isn't a fresher filter | The LLM `fresherFit` tag; the site shows fresher-friendly posts by default |
| 17 Nov | Adzuna `created` timestamps are a few hours **in the future** | "Posted in 4 hours" would look broken | Cap future timestamps at the current time during normalisation |
| 17 Nov | 171 of 529 posts have no city in the location field | The rule-based city parse can't cover them | The LLM reads the description; otherwise "India (unspecified)" |
| 17 Nov | The stored `ANTHROPIC_API_KEY` was rejected (401): it isn't an Anthropic key (`sk-ant-…`) | Tagging calls failed | Failure handling worked: no crash, $0 charged, posts published untagged and retried next run. Needs a real key |
| 17 Nov | `.gitignore` was written for Maven, so Gradle's `build/` and `.gradle/` were staged; `gradlew` would get CRLF line endings on Windows | Would break the Linux CI runner | Fixed `.gitignore`; added `.gitattributes` (LF everywhere) |
| 17 Nov | Decided not to pay for an LLM; switched to free tiers. Groq's free tier allows ~1,000 requests/day but only **200K tokens/day and 8K tokens/min** per model. One post per request costs ~2K tokens (the instructions are ~1.8K), which would allow only ~90 posts a day | Token limits, not request limits, are what bind | **Batch 8 posts per request**: instructions sent once per batch, ~500 tokens per post, so ~400 posts/day. Requests spaced 35 s apart |
| 17 Nov | Free tiers can run out mid-run | A daily job must not stop halfway | Providers are tried in order (Groq, then Gemini). A daily-limit 429 or rejected key switches provider; a per-minute 429 waits for `retry-after`. Anything left is tagged on the next run |
| 17 Nov | Tag cache was keyed by model, so falling back to another provider would re-tag every post | Wasted quota | Cache key is prompt version + post text; each post records which `provider:model` tagged it |
| 17 Nov | Gemini returned 404: `gemini-2.5-flash` "is no longer available to new users" (the log showed only `[{`) | Model names retire; bad error logs hide the cause | A 404 switches provider instead of retrying; the log now shows the provider's error message; model set to one the key can actually use |
| 17 Nov | First full tagging run: **538 posts in 68 requests, 39 min, $0**. Groq hit its 200K tokens/day limit after 62 requests (~496 posts), as planned; Gemini took over automatically for the last 50 and recovered from one 503 by waiting and retrying. 0 failed posts | The fallback chain worked on its first real run | ~520 tokens per post. At Groq's paid price that is **$0.14 per 1,000 posts**; actual cost $0 |
| 17 Nov | 112 of 546 posts ended as "India (unspecified)" and 477 have work mode "unknown" | Source posts often don't say; Adzuna descriptions are cut at 500 characters | Expected; the 50-post hand check will show whether these are model misses or genuinely missing |
| 18 Nov | v2 put the 96-skill list in the JSON schema as an enum. **Gemini refused the schema** ("too much branching") and **Groq sometimes broke its own strict check** (an implied skill off the list) | Whole batches failed | Skill list moved into the prompt text; Java drops any name not on the list (case-insensitive) |
| 18 Nov | A new prompt version means every post needs new tags, but Groq's daily limit is a rolling 24 h and was still used up from the day before | The run would have published mostly untagged posts | Stopped the run before it wrote anything. Posts not re-tagged now **keep their earlier tags**; this also protects daily runs when a provider is down |
| 18 Nov | v2 run: **611 posts in 77 requests, 20 min, all on Gemini, 0 failures, $0** (≈$0.32 per 1,000 posts at Gemini's paid price). Posts with no skill information fell from **42% to 4%**; the Australian hospital job was removed by the India check | Best fit matching now has data to work with | A DSA + Java + SQL profile gets 113 matches, top 12 all software roles, including posts that never say "DSA" |
| 18 Nov | Gemini Flash-Lite marked senior doctors ("Consultant Orthopaedic Surgeon") as fresher-friendly despite the v2 rule, and tagged an electrical field-service job as Software Engineering | The fallback model is weaker than Groq's | Measured in the 50-post hand check; compare the two models there |
| 18 Nov | `gradlew` was committed from Windows without the executable bit | The Linux CI runner would fail on its first step | `git update-index --chmod=+x pipeline/gradlew` |
| 18 Nov | Vercel CLI deploys upload local files, which would include the private `docs/email.md` | Privacy | `.vercelignore` uploads only `web/` and `vercel.json`; checked that `/docs/email.md` returns 404 on the live site |
| 18 Nov | A "Sr. Software Development Engineer" card showed no skills although the real post lists Java/Python, cloud, ML and 7+ years | Adzuna's API returns only the first 500 characters, here the company's mission statement. Adzuna's website answers automated requests with **403 "Request blocked"**, so fetching full pages would break its terms | Not scraped. Cards now label role-implied skills ("Usually needed for this role") and say "Preview only, read the full post" when the text was cut |
| 18 Nov | The weaker fallback model still marked some senior titles fresher-friendly | Students would see senior jobs under "fresher-friendly" | Rule-based safety net after the LLM: Senior/Sr./Lead/Principal/Architect/Director and specialist-doctor titles are always "not fresher". Applied to cached tags too: 12 posts corrected with no LLM calls |
| 18 Nov | A "Mechanical Engineer" post needing **3–15 years** showed under "Fresher-friendly only". Adzuna's `trainee` search matched "Supervises: Associate/Trainee Engineers"; the experience line was past the 500-character preview, so the model correctly said **unclear** | My filter only hid "no", so all **139 "unclear" posts were shown as fresher-friendly** (482 instead of 343) | The default Experience filter is now strict, "Freshers welcome" (fresherFit = yes only), with "Freshers + not stated" and "All posts" as opt-ins. Unclear cards show an "Experience not stated" badge; header and stats count only "yes" |
| 18 Nov | Asked to make sure every post's skills, experience and location are right | The LLM reads loosely and only sees a 500-character preview; a pricier model can't read text it never gets | Added **rule checks after the LLM** (`TagRules`), each recorded on the post as `fixes`: experience stated in the text ("3-15 years of experience"), senior titles, specialist doctors, "Intern" → internship, the location field beats the model's city, and skills the post "names" must actually appear in its text. 66 of 618 posts corrected, no LLM calls |
| 18 Nov | Reviewing every rule correction by hand exposed rule bugs: "Lead Generation Specialist" read as senior; "Age Limit Maximum 29 Years" read as 29 years of experience; "Fresher – 2 years" and "up to 2 years" read as 2+ years; skills the model invented were being shown as "usually needed" | Rules can be wrong too | Tests for each case (30 tests). Invented skills are dropped, not moved |
| 18 Nov | "Collections Manager" in **Hubli** was shown in **Ranchi** | Hubli wasn't a known city, so the post looked city-less; dedup treats no city as a wildcard and **merged two different posts** | Unknown first part of the location is now kept as the city (states and "India" excluded) |
| 18 Nov | Recognising more cities changed some post ids, and the site showed the same job twice (old id and new id) | Duplicates on the page | Yesterday's posts are matched to today's by link as well as id; old copies with a link fetched today are dropped. 0 duplicate links |
| 18 Nov | Specialist-doctor posts say "Freshers and experienced candidates may apply" | For doctors "fresher" means a newly qualified specialist, not a college graduate | Specialist-doctor titles are always "not fresher", whatever the text says |
| 18 Nov | With no LLM key the pipeline skipped tagging entirely, so even cached tags and the rule checks weren't applied | One expired key would degrade the whole site | Cached tags and rule checks always run; only fresh LLM calls need a key |
| 18 Nov | Wanted the strongest model without paying for API credits | Free API tiers cap the daily tokens; the weaker fallback model made more mistakes | **Tagging by a scheduled Claude Code routine on the Pro plan.** The GitHub Action writes `state/pending-tags.json`; the routine tags those posts following `tagging/ROUTINE.md` and prompt v3, checks its file with `tagging/check-tags.mjs`, and pushes it; the push triggers the Action, which re-checks every tag in Java and republishes. Groq/Gemini now tag only brand-new posts, as a same-day fallback |
| 18 Nov | Prompt v3: descriptions are previews, so a missing requirement isn't "no requirement" | v2 sometimes said "yes" to fresher fit when the experience line was simply cut off | `fresherFit` is "unclear" unless the post signals early-career |
